## Bug 分析

### 问题所在

`elif` 和 `else` 分支中的 `+=` 和 `-=` **写反了**：

```python
elif n == candidate:
    count -= 1   # ❌ 遇到相同元素却减少了计数
else:
    count += 1   # ❌ 遇到不同元素却增加了计数
```

### 正确逻辑

Boyer-Moore 投票算法的核心思想是：
- 遇到**相同**元素 → 计数**增加**（`+= 1`）
- 遇到**不同**元素 → 计数**抵消**（`-= 1`）

### 修复后的代码

```python
def majority(nums):
    count = 0
    candidate = None
    for n in nums:
        if count == 0:
            candidate = n
            count = 1
        elif n == candidate:
            count += 1   # ✅ 相同元素，计数增加
        else:
            count -= 1   # ✅ 不同元素，计数抵消
    return candidate
```

### 用反例验证 bug

以 `nums = [1, 2, 1, 1, 3]` 为例（正确答案是 `1`，出现 3 次 > 5/2）：

| 步骤 | n | 原代码执行 | count | candidate |
|------|---|-----------|-------|-----------|
| 1 | 1 | count==0 → 设 candidate=1 | 1 | 1 |
| 2 | 2 | n≠candidate → count **+=** 1 | 2 | 1 |
| 3 | 1 | n==candidate → count **-=** 1 | 1 | 1 |
| 4 | 1 | n==candidate → count **-=** 1 | 0 | 1 |
| 5 | 3 | count==0 → 设 candidate=3 | 1 | **3** |

原代码返回 `3`（错误），修复后返回 `1`（正确）。

### 根本原因

原代码把"相同元素增加票数、不同元素抵消票数"的逻辑完全颠倒了，导致多数元素的票数被错误地消耗掉，最终可能选出少数元素作为 candidate。
